## 3. Proposed contracts and validations

### 3a — IF-LAUNCH: prompt return, terminal-owned lifetime

**◇ Proposal:** Register distinctly named underscore-form Rex configuration actions; proposed product names are not existing Rex APIs. The launch action validates origin/configuration, reserves bounded state, resolves the current origin window, creates a native terminal layer using session.new_layer, records returned layer/block IDs, and returns promptly. It must not wait for human menu interaction within the configuration action's documented 30-second lifetime.

The terminal block owns the Go process lifetime. Do not substitute an ordinary action-owned rex.exec child, which normally dies when the action returns. Direct executable argument arrays should replace the fixture's shell wrapper where the installed terminal creator supports them; the retained fixture already supplies a command array but includes Bash and fixed temporary paths.

Keep these identities separate: target endpoint and server instance, configuration runtime generation, originating app client, originating session and block, launch-time window, popup layer and popup blocks. The launch-time window is diagnostic placement data, not permanent origin identity. Capture full IDs, never labels as unique identity. Do not infer the origin app from the popup's later CLI connection or automatically select the sole connected app.

**? Validate:** Missing origin, partial creation, immediate terminal exit, size ownership and explicit focus behavior need isolated tests. session.new_layer defaults focus=false; choosing focus=true for an interactive menu is provisional and requires real-app focus/restoration verification. Do not retry layer creation merely because rex wait cannot resolve a vanished short-lived block.

### 3b — IF-CONFIG: one explicit configuration table

**◇ Proposal:** Ship an integration module named rex_whichkey and use a different user-module name, such as whichkey_user_config. Candidate usage is require('rex_whichkey').setup({...}) or require('rex_whichkey').setup(require('whichkey_user_config')). These are proposed product interfaces, not published Rex functions.

One table is supplied per setup call. Defaults fill absent values; there is no implicit inline/file merge. Reject duplicate setup rather than silently replacing live callbacks. Compile and validate a replacement before publishing it if explicit replacement is later introduced. Rex itself does not supply this precedence rule.

Lua evaluates conditions and function-valued labels in the captured runtime/context and retains callback closures and original action arguments. Export only bounded display/navigation data and opaque mapping identities. Go must not receive serialized function bodies or evaluate Lua.

**? Validate:** Real-server sibling require worked historically. Duplicate setup, default precedence, malformed configuration, function errors, module-name collisions, package-installed search paths and preservation of the last working configuration still need fixtures. Reload invalidation was demonstrated, but failed reload behavior must not be inferred from it.

### 3c — IF-DISPATCH: data-only, invocation-bound selection

**◇ Proposal:** A versioned menu snapshot contains display/navigation data, runtime generation and opaque invocation/mapping references. A selection contains only version, invocation reference, selection reference and confirmation/cancellation state. Arbitrary action names, callback code, replacement args, server selectors or filesystem paths supplied by a selection are rejected. Lua resolves the action and args from its retained entry.

Proposed lifecycle: Reserved → Open → Consumed, Cancelled, Expired or Invalidated. Only Open can be selected. Validate schema, size, capability, generation, deadline, allowed mapping, confirmation, current conditions and origin before consuming. Unknown or malformed selections never execute callbacks. A stale condition invalidates that selection; do not silently dispatch its old snapshot meaning.

Consume the invocation before any callback, queued app action or yielding side effect. Reentrant dispatch and replay then fail. Authenticated cancellation consumes without invoking a callback. Callback failure does not restore the invocation. Partial callback side effects may already exist: return a bounded error and never automatically retry. Timeout or disconnect after submission means outcome unknown, not safe-to-repeat failure, especially for destructive actions.

Store callback references only while needed. Candidate initial bounds are a 120-second maximum invocation age, 16 live invocations per runtime, one live menu per originating app/block, a 1 MiB snapshot, 64 KiB selection and 4096 compiled entries. These numerical limits are proposed, not measured acceptance thresholds. Reject excess before allocating resources; expire lazily at every entry point and investigate a supported configuration-runtime timer for proactive cleanup. Bound consumed-state retention by the same lifetime/capacity budget, or remove live entries and reject all unknown references. Never evict a live invocation and then accept its old capability as new.

**Crash/reload semantics:** Config reload or server/runtime replacement invalidates all old entries; old capabilities must never select newly registered callbacks. Runtime generation must not restart with a reusable predictable namespace. A Go crash cannot trigger the selected action; cleanup is best effort plus bounded expiry. A crash after callback side effects may leave an unknown outcome. Reentrancy with a new invocation must obey the same per-origin cap and must not reactivate the consumed invocation.

**Ordering remains a gate:** Intended order is authenticated selection acceptance, consume, popup removal verified, current-origin focus, callback/configuration action return, then queued app action. The retained harness neither stores the popup ID in invocation state nor explicitly closes it before callback dispatch. Closing a popup that contains the submitting process may kill that process. Do not rely on that process performing another RPC afterward. A short-lived handoff to the persistent Lua dispatcher/controller is a candidate, but its ability to continue after popup destruction and preserve queue delivery has not been demonstrated. No additional daemon is proposed. Exact handoff and acknowledgement mechanics remain unresolved.

### 3d — Security and origin ownership

**◇ Proposal:** Generate a minimum 256-bit capability using Go crypto/rand in a short helper invocation, called from Rex Lua with documented rex.exec(argv, opts). Return a narrowly validated encoding and fail closed on entropy/helper failure. No CSPRNG Lua API was established; do not substitute math.random, timestamps, fixture IDs or assume UUID APIs exist. Availability, runtime location and latency of this helper on supported Rex versions require a real configuration-action test.

Documented rex.exec has argument arrays and a stdin option. That does not establish a stdin injection channel for a newly created terminal block. A capability supplied in terminal command argv, environment, selection CLI args or retained session metadata can be visible to local observers. It is therefore a bearer capability within a trusted same-user/server boundary, not a secret from that user, privileged processes or server administrators. Prefer a bounded owner-only server-local file or verified private channel if one can be demonstrated without unsafe path assumptions. This alternative is also unvalidated; do not promise cross-user isolation from argv transport.

A bearer capability authorizes one invocation; it does not prove graphical-app ownership. ctx.origin is diagnostic and can be api even for CLI invocation. A client ID, client.inspect result or -C selector identifies/routes a client but is not independently sufficient authorization. Production ownership requires trustworthy server-supplied connection provenance at launch, binding of that authenticated provenance to the retained invocation, and an authorized return channel. Whether Rex exposes enough provenance and delegation for this path remains unproved. If the available context can be nominated by an untrusted caller, reject rather than bless it using ID equality. Do not claim a production ownership contract until the positive and spoofing-negative tests pass.

Redact capabilities and callback args from logs and diagnostics. Bound CLI output, error text, decoding depth and timeouts; reject unknown protocol versions. Strip or encode terminal control sequences in user-controlled labels while preserving valid Unicode. Escape parsing must not convert terminal replies into menu keys.

### 3e — IF-REX: concrete typed candidate grounded in actual methods

**◇ Proposal:** The following Go signatures are candidate wrappers, not claims of existing Go or Rex APIs:

```go
type Client struct { /* private CLI runner and explicit target */ }
type Session struct { /* client + stable session ID */ }
type Window struct { /* session + window ID */ }
type Block struct { /* session + block ID; window not identity */ }

func (c *Client) Call(ctx context.Context, method string, params any, out any) error
func (c *Client) Sessions(ctx context.Context) ([]Session, error)
func (s Session) View(ctx context.Context) (SessionView, error)
func (s Session) NewLayer(ctx context.Context, p NewLayerParams) (NewLayerResult, error)
func (s Session) ResizeLayer(ctx context.Context, layerID string, bounds [4]float64) error
func (s Session) CloseLayer(ctx context.Context, layerID string) error
func (b Block) Focus(ctx context.Context) error
func (b Block) Method(ctx context.Context, method string, args any, out any) error
```

Exact method mappings from retained installed schemas:

| Candidate operation | Actual Rex method and fields |
| --- | --- |
| Sessions | session.list, empty object |
| View/current block location | session.view, session_id; traverse windows/layers/blocks |
| NewLayer | session.new_layer: session_id, optional window_id, bounds, layout, focus; response layer_id, block_ids, revision |
| ResizeLayer | session.resize_layer: session_id, layer_id, bounds |
| CloseLayer | session.close_layer: session_id, layer_id |
| Block.Focus | session.focus_block: session_id, block_id; containing window becomes active |
| Block.Method | block.method: session_id, block_id, method, args |

There is no proposed dependency on invented session.windows, window.blocks, block.info, client.register or client.identify methods. Window values and block containment can be derived from session.view until a separately verified operation warrants another wrapper. Preserve explicit session identity when a block moves between windows. If it disappears or changes session unexpectedly, fail stale rather than searching unrelated sessions for an apparent match.

Generic calls use an argument-array equivalent of rex --autostart=false --server ENDPOINT api call METHOD JSON. Serialize JSON as one argument, not shell syntax. Keep the configured target immutable for an invocation; do not silently fall back to another server. Test invalid JSON, nonzero exit, cancellation, timeout, argument metacharacters and mismatched targets with a private runner seam.

App actions are separate from server methods. client.action runs configuration/block actions and returns ordered client_actions; it cannot directly execute pane.split. The older server documents client.perform(client_id, action, args, optional session_id/block_id/timeout_ms), but does not validate the forwarded session/block fields as ownership. CLI rex -C CLIENT do ACTION is documented routing, not demonstrated delivery here. Do not add a public Perform wrapper until origin authorization and end-to-end routing are proven. pane.split action directions up/down must not be confused with CLI above/below.

### 3f — IF-HOSTS and remote runtime/path ownership

**◇ Proposal:** List the effective inventory of the machine executing the menu's rex CLI, including its configured home merge. Display that ownership explicitly. This is a provisional user-visible choice, not acceptance of originating-app/home ownership equivalence.

Use rex hosts --json, preserving stable host IDs, labels, per-entry from/held, home/cached status and warnings. Local duplicate labels win in the documented merge. --server and REX_SERVER do not retarget this command. Raw hosts.list is one server's inventory, not the effective merged CLI result. Do not silently substitute it or create an independent registry. Initial host entries list information only; selection does not start deferred attachment or bootstrap flows.

The configuration Lua runtime, its imported user file and callbacks live on the target Rex server host. The terminal executable, helper and installed integration assets must exist where that server launches the terminal process. Resolve the Rex endpoint from that process's runtime context; a graphical client's Unix-socket path is not portable to the server host. Preserve target server identity independently from origin app identity. No capability, snapshot or module path may assume a client-local /tmp or Nix store path exists remotely.

**? Validate:** Real remote menu/config/callback operation and endpoint propagation remain unmet. Historical remote whoami established reachability/identity only. If originating-client/home inventory is preferred, that needs an explicit alternative contract and verified data transport; do not pretend --server implements it.

### 3g — IF-TUI, geometry and delegated actions

**◇ Proposal:** Keep pure menu/navigation state independent of the renderer without introducing architectural layers. Investigate the existing Open terminal candidate: Bubble Tea v2.0.8 with an isolated correction to x/ansi v0.11.7, not an adopted fork. Direct rendering with a real buffered input reader remains a research alternative.

The new terminal source trace identifies the unconditional ASCII shortcut splitting e + U+0301 in both width modes. Ultraviolet subsequently loses or misplaces the detached mark on the retained path. The audit confirms this narrow diagnosis and warns that trailing/isolated marks and control boundaries need separate tests. Forcing mode 2027 or normalizing to precomposed text is not an accepted fix.

The unchanged direct probe treats the ESC starting an OSC reply as cancellation. A decoder called on individual bytes is not a buffered reader. The audit identifies split ST terminators as an additional source-derived risk, not a reproduced runtime failure.

The retained timing comparison measured 20 warm-local samples: direct/Bubble Tea first-content medians about 15.1/34.0 ms and selection-to-restored-exit medians about 17.4/17.7 ms. These include PTY/shell overhead, exclude callback RPC, and are not real-app pixel or remote latency. No product threshold exists; speed does not waive correctness.

Native fractional geometry is preferred for investigation, not yet accepted. Test top/bottom/left/right/center with edge markers, opacity and offset x>w cases. Server bounds and forced 40x12 captures passed historically; actual clipping and client-owned resize did not. Keep old full-window overlay behavior as an alternative only if current native behavior genuinely fails and a workaround is separately evaluated.

Preserve delegated session.switch picker parity. Old configuration maps statically to Rex's picker; it does not establish a required enumerated WhichKey session submenu. The older app advertises session.switch and distinct session.select. Interactive cancel/select behavior remains untested.
